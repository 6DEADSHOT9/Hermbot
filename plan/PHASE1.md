The tests caught and fixed concrete integration issues: Hermes defers plugin tools by default, session titles must be unique within a runtime, and the newest automatically resolved Rollup version exhausted memory. The POC exposes the small collaboration toolset directly, uses session-specific titles, and pins the verified build dependency. Browser validation also caught the need to generate request IDs on plain HTTP origins; the UI now uses cryptographically generated bytes. The final mobile check exposed overflow with a long group list; groups now scroll within the sidebar while owner controls remain available.

Recovery tests cover duplicate owner submissions, duplicate tool receipts, scope-bound authority, cancelled reviews, private artifact access, checksum validation, worker leases preserving the same immutable request, uncertainty retaining a bot slot, failed-child continuations waking once, dependency rewiring on reassignment, grant revocation leaving unrelated work alone, and steering receipts preventing ambiguous automatic replay.

The durable protocol receipts are exported to `test-results/protocol-acceptance.json`; those checks used synthetic model responses and are labelled accordingly. `test-results/execution-evidence.json` records the separate real-model task IDs, native execution IDs, tool receipt counts, event counts and artifact counts. `test-results/container-isolation.json` records selected mount/network metadata without environment secrets. Deliberately interrupted and cancelled test tasks remain visible as acceptance history.

The active-worker proof's terminal-start event and settled-attempt timestamp bracket the worker restart at `2026-10-06T09:10:09Z`. The browser proof submitted an actual UI request, closed its context while the task was running, waited for completion outside the browser, then opened a new context and read the saved artifact.

Current practical limits are deliberate POC bounds: three fixed bots, local owner authentication, bounded text artifacts, one active execution per bot, one-shot native schedules reserving an idle bot, and no connected-app integrations. An uncertain scheduled execution remains reserved until its native execution is reconciled; deleting a native job alone does not prove that a running executor has exited.

Evidence files and screenshots are under `test-results/`. At Phase 1 closure, [CHECKLIST.md](CHECKLIST.md) marked only Phase 1 complete. The original thread and approved plan remain unchanged in `plan/archive/` and `plan/README.md`.
