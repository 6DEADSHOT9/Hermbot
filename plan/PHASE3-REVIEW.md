# Phase 3 code review

Review scope: library provenance and access, uploads and public-link ingestion, immutable objects/versions, document previews, native knowledge writes, learning proposals and approval replacement, runtime refresh ordering, persistent computer control, tool admission and owner input, authenticated screen relay, browser persistence, and asynchronous web-panel state. Phase 4 and remote hosting are outside the owner-authorized scope.

The review was completed after the real Phase 3 exit gate, with earlier implementation findings retained below. Every listed finding was corrected and verified before closure.

| Finding | Correction | Verification |
|---|---|---|
| An upload accepted spaces and Unicode in a filename, but the supervisor attachment schema rejected them at dispatch. | Use one plain-filename contract through upload, attachment transport and secure installation; reject `.`/`..`, path separators and control characters. | Regression cases include `résumé 2026.csv`, dot filenames, checksums and descriptor-based installation. Real native library and Phase 2 attachment runs passed. |
| Office XML entity checks could miss UTF-16/UTF-32 declarations; compressed content could consume excessive preview memory. | Check normalized declaration bytes before parsing, bound total decompression to 2 MB, limit selected sheets and cap preview text. | UTF-16 DTD/entity and decompression regressions, real DOCX/XLSX extraction and original-byte downloads. |
| Link import could reach private infrastructure through redirects or DNS changes, and a continuously dripping response could defeat socket timeouts. | Validate all resolved addresses at every redirect, connect to the validated numeric IP, verify TLS against the original hostname, and avoid environment proxies. Bound redirects/bytes and interrupt response headers/body at a wall-clock deadline. | Private-address, redirect, authentication/port and bounded-response tests; an actual dripping HTTP server was stopped by the deadline; actual public-link import. |
| Chromium blocked PDF previews inside a sandboxed frame. | Serve PDF with fixed `application/pdf`, `nosniff` and same-origin framing policy so the built-in viewer works. Other content retains the restrictive sandbox policy. | Fresh Chromium preview with actual rendered PDF text, downloaded bytes and content headers. |
| Native memory writes could follow unsafe directories/files or hang on a FIFO; concurrent CAS could overwrite another edit. | Use directory/file descriptors with `O_NOFOLLOW`, require regular UTF-8 files, use nonblocking file opens, and serialize writes with a cross-process lock and atomic fsynced replacement. | Symlink, stale-hash, same-content replay and concurrent-writer regressions. Actual memory edit/removal/restoration and immutable history. |
| Invalid bot configuration could be rejected after native knowledge had already changed; a skill description could have a non-string YAML value. | Validate the complete future configuration before the native write; require a matching name and nonempty string description. | Invalid-permission/configuration and frontmatter regressions; real skill import, enable, versions and removal. |
| Hermes caches memory/skill configuration, so saving disk content alone did not guarantee the next model run saw it. | Queue a durable runtime refresh, clear readiness, and resume approved learning only after its definitive receipt. Replay native writes with the same frozen CAS after uncertain transport. | Learning outbox, stale revision/hash, failed refresh, cancellation/revocation and busy-runtime regressions; actual `skill_view`, owner-edited learning, refresh and continuation. |
| Edited review drafts could reuse an approval for different content; model proposals could invent their own expected hash/revision or cross-bot authority. | Replace the approval with a new exact payload/hash and supersede the old one. Freeze native hashes/revisions on the server; recheck current management authority before application. | Old-decision HTTP 409, expiry/cancellation/grant regressions, real learning review and generic review UI. |
| Generic “Allow once” wording did not tell the model that requested secure input was finished. | Give secure input its own metadata-only schema, computer link and “Input completed · continue” action. Require explicit handback, then say completion is acknowledged without returning input. | Secure metadata/handback regression and successful real manager/Scout/Quill exit task. |
| Takeover could enable human input before an already admitted native tool finished. | Set human ownership first, then wait for the shared tool-execution mutex; input becomes ready only for the matching native lease epoch/viewer. Later tools pause and the task waits durably for explicit handback. | Real foreground terminal test: takeover waited 8.136 seconds, effect count stayed one, and the native turn paused/resumed. |
| An unavailable adapter or recreated runtime could leave database dispatch unaware of human ownership. | Commit the database admission fence before native takeover, recheck it during claim/dispatch and native tool context, and preserve it until explicit handback. | Unreachable-adapter database-fence, pending dispatch and durable pause regressions. |
| Status/control and desktop mutation requests could race between owner sessions. | Serialize status, takeover, handback, start, stop and browser launch with the same per-bot advisory lock. Native input remains independently epoch fenced. | Concurrent stop/takeover regression, live competing-session/stale-handback/reclaim checks. |
| If the desktop stopped unexpectedly during human control, the UI hid handback along with running-desktop buttons. | Keep explicit handback available even when the desktop is stopped. | Injected a real native desktop stop while a human held control; owner UI released both native lease and database fence, then restarted the desktop. |
| A late knowledge/file response could populate or close a panel after switching teammates/conversations. | Scope callback generations to the panel opening and target; retain the original operation while suppressing stale draft, file-chip, error and busy-state updates. | Browser held real skill/file-use responses across closing and changing targets; no stale draft or attachment appeared and the new panel stayed open. |
| New group selection could reset to an older chat before its metadata reached the cache. | Refresh the conversation roster before selecting the new group, so active-conversation recovery sees the new ID. | Real UI group submission and active browser-disconnect/reconnect acceptance. |
| Native desktop startup inherited the wrong home/runtime directory; Chromium's old-host singleton files blocked a persisted profile after recreation. | Initialize private directories/ownership before dropping to UID 10000, set the native home/XDG runtime, and remove only verified ephemeral Chromium singleton/port files during startup. Retain all profile/session data. | Real desktop/browser startup and owner lifecycle recreation with the same private volumes and a persisted cookie; cleared secure-input form stayed cleared. |
| Screen input could outlive an owner session or silently release control on disconnect. | Authenticate same-origin WebSockets, keep private native keys server-side, recheck session validity, bound traffic and filter native RFB input by lease epoch/viewer. Disconnect retains human ownership. | Unauthenticated/cross-origin socket tests, actual noVNC keyboard input, reconnect, competing owner sessions, epoch fencing and explicit handback. |

Final validation: 85 backend checks (all 51 earlier Phase 1–2 checks plus 34 Phase 3 checks), Ruff and TypeScript/Vite production build. Real native/model acceptance covers the library, curated memory/skills and learning, computer control, structured reviews, orchestration exit, and cumulative earlier lifecycle/collaboration/recovery checks. Evidence and completion audit are indexed in [PHASE3.md](PHASE3.md).

Practical boundary: control exclusion applies to admitted native tools and foreground in-flight tools. It is not an OS guarantee that stops arbitrary background processes launched earlier by an owner-trusted bot. Secure input travels over the live desktop connection and is omitted from product transcripts; it is still delivered to the destination application. The acceptance run used a dummy canary on a local-only form. DOCX/XLSX previews extract bounded text; full layout remains available through the original download. Linux hosting/HTTPS is deferred. These are documented scope limits, not claims of later-phase isolation or integrations.
