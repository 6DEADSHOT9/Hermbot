## Use

Open **Routines → Events → Sources**. Add a source, save any required private credential and inspect its status. Create an event trigger with its event types, conditions, teammate, results conversation, saved instructions and expected results. **Save draft trigger** stays inactive; **Start listening when saved** activates it. Preview checks normalized sample facts and current access without creating work or performing actions. The form can select the same shared files, attachments, enabled skills and active work budget as a scheduled routine.

| Source | Local transport | Supported input and setup |
|---|---|---|
| Slack | Outbound Socket Mode; optional signed HTTP | New messages and app mentions in one explicitly selected conversation ID. Use a bot connection plus a private app-level `xapp-` token with `connections:write`. Enable Socket Mode, subscribe to `app_mention` and/or the appropriate message events, add the required Slack read scopes and reinstall if scopes change. Invite the app to the selected channel. One configured workspace per Slack app; reuse its source across triggers. A bot OAuth token alone cannot open Socket Mode. |
| GitHub | Polling; optional signed HTTP | New issues, issue/PR comments and observed issue/PR updates in one owner/repository. Use the existing connection with repository read access. Polling respects ETags, rate limits and provider poll intervals. Signed HTTP uses the repository webhook secret and supported issue/comment/pull-request events. |
| Google Drive | Changes API polling | File changes, removals/access loss, file IDs, direct parent folder IDs and MIME types. `root` is resolved to the actual parent ID. Folder conditions cannot classify removal events because prior parent membership may be unavailable. |
| Google Calendar | Incremental sync polling | Added, updated and cancelled entries in one selected calendar, including `primary`. Initial pages establish a baseline; expired sync tokens require an explicit new baseline. |
| Gmail | History API polling | Added messages with label, actor, text and message-ID conditions. Collects bounded metadata/preview context; it does not automatically fetch full bodies or attachments. Expired history requires a new baseline. |
| General webhook | Signed HTTP | Standard Webhooks: `webhook-id`, `webhook-timestamp`, `webhook-signature`. Generate or privately enter a `whsec_` key. Send JSON with `type`, `resource`, `text`, and optional `occurred_at`, `actor`, `version`, `summary`, `data`. HMAC-SHA256 signs the exact `id.timestamp.raw-body`; send its base64 digest prefixed with `v1,`. |

Slack/GitHub signatures are checked against the raw body. Slack and general webhooks have a five-minute timestamp tolerance. GitHub uses its delivery ID and signed body; it has no equivalent authenticated delivery timestamp. HTTP bodies are limited to 1 MiB and ten seconds. External HTTP senders require reachable ingress; this build does not expose the machine, configure a tunnel or deploy HTTPS. Socket Mode and polling need outbound access only.

## Execution and recovery

The event collector is a separate Compose service, `event-worker`, with database/encryption access and no Docker socket or model credentials. Provider calls run outside database transactions. Sources have fenced leases; a superseded collector cannot advance a cursor. Each page commits its events and continuation/cursor together. HTTP/Socket acknowledgement follows the database commit. Normal processing does not depend on an open browser.

Delivery identity, logical event identity, trigger match and work occurrence are separate durable records. Provider redelivery cannot create another occurrence. An owner revision supplies instructions, results and authority; provider text is quoted, untrusted context. Each admitted occurrence creates an ordinary work item, thread, task and native session through the same path as scheduled work. Hermes itself is unchanged. A saved trigger does not copy an **Allow once** decision or grant management authority. Connected-app actions still require current connection permissions and the existing request/review/receipt rules; enabled native tools remain available.

One unfinished occurrence runs per trigger. Active/retried work and uncertain results or connector operations block overlap. Other matching events remain pending rather than being treated as completed or silently skipped. Configurable daily admissions, pending capacity, active budget and maximum start delay bound consumption. Blocked triggers rotate behind other eligible work. Exceeding pending capacity pauses the trigger and cancels its unstarted occurrences with recorded reasons. Expired occurrences stay inspectable.

Combining updates is optional and available only for latest-state events: Drive changes, Calendar updates and GitHub issue/PR updates. It combines the same resource and event type, up to 100 updates, with a quiet period and maximum wait. The task receives the latest fact and event count; this is not a promise to execute every intermediate transition. Slack message/mention callbacks for the same message share one occurrence per trigger.

Pause/archive/edit cancels pending and queued, never-started work transactionally. Started work continues under its saved revision until the ordinary Stop action. Connection changes, revocation and unavailable conversations pause affected triggers. Source setup and signing-key rotation invalidate the old binding; check the source and save each trigger against its current revision. Old signing keys can overlap for an explicitly bounded rotation period. Archiving a source removes its private signing/app token and prevents reactivation; history remains. A new source can be created for the same scope.

New/resumed polling triggers start after an explicit listening baseline; historical input is not replayed. A cursor expiry is shown as **Needs a new baseline**, rather than silently resetting it. Slack reconnection records a gap; its recoverable history depends on Slack's delivery retention. Stale collector check-ins show **Collector disconnected**. Unsupported, ignored, matched, duplicate and recording-failed deliveries remain distinguishable. Only a retained recording failure with unchanged source authority can be reprocessed; existing work uses its ordinary retry action.

Self-trigger prevention uses the connected Slack bot identity and successful Hermbot connector receipts correlated with exact provider resource versions. Drive also compares its returned file state (name, MIME type, modification time, parents and trash/removal status), because its server version can advance without a visible file change. Polling skips later version-only changes to the same observed state. For a newly observed Google Doc carrying this application's private operation marker, the collector checks a successful post-baseline creation receipt and verifies the initial approved plain text, name and parent with one read-only export. This handles conversion changing modification time after the create response. The check runs outside database transactions; its proof is bound to the observed file state and retained atomically with polling progress. Later edits are handled normally, including text edits before the first observation. Drive pages are limited to ten changes to keep possible initial exports within the collector lease. Changes outside those observed fields, including permission-only changes and rich-format-only edits before the initial text comparison, are outside this trigger's change detection contract. Admission checks again after operation receipts settle, before applying the daily admission cap. Merely sharing the same human account does not suppress legitimate new input. This is bounded correlation, not universal prevention of automation loops: independently authenticated native actions, unrelated integrations and versionless provider changes can fall outside it. Daily/backlog limits and owner inspection remain necessary.

Event payloads are encrypted and retained for seven days; pending normalized context remains until its occurrence settles. Unmatched events retain bounded identity/summary and matching decisions rather than full payloads. Consumed identities remain after content expiry to prevent old redelivery becoming new work. Admitted task context follows the application's existing work-history retention. This local owner workspace supports 100 live sources, 100 nonarchived triggers per source and 10,000 distinct deliveries per source per rolling day. Sources list live sources plus the latest archived setup history; the archive listing is bounded to 200 total. Work/event/delivery histories have cursor pagination.

### October 25 live provider acceptance

[Durable provider evidence](../test-results/phase52-provider-events.json) records the owner's exact approvals, successful provider IDs and completed reports for actual outside-Hermbot changes in all five services. The Slack message and app-mention callbacks share one occurrence. Creation echoes do not count as external-input acceptance. The collector/application restart preserved the saved listening cursors and report history. The four legacy canary tasks initially failed stale preparation after reporting successful receipts; guarded report-only recovery refreshed their preparation and completed all four without repeating the effects. Original failures remain in task events/attempt history.

The first converted Google Doc returned version 4; polling observed versions 6 and 7 and started two unwanted reports before the owner's genuine rename. That failure is retained. A fresh, separately owner-approved Google Doc demonstrated that conversion also changes modification time after the response, so state comparison alone was insufficient. The final collector check verified that actual document's approved initial text/name/folder against a real read-only export. A guarded replay applied that exact collector check to its retained, never-admitted event; ordinary admission then marked it ignored without creating a task. This used the already successful write, preserved the original event, and made no additional provider mutation. Automatic collection/atomic proof persistence, invisible version changes and human text edits before/after the first observation have isolated regressions. [Live proof](../test-results/phase52-provider-events.json), [547 backend tests](../test-results/phase52-provider-backend.xml) and the canonical [issue register](ISSUES.md) record the precise scope.

The acceptance group and five test triggers are archived. All receipt, failure, correction and result histories remain inspectable. Five configured sources remain under ordinary provider names for reuse, including the privately saved Slack app token; with no active triggers they do not create work. External test documents, messages, calendar event and GitHub issue were not deleted. The [final audit](../test-results/phase52-provider-final.json) confirms 13 completed fixture tasks, six exact owner-approved writes, five single-report external changes, preserved original failure events and no pending fixture work or approvals.

Not verified: public HTTP ingress and production load. Polling cannot reconstruct every intermediate change overwritten between checks; GitHub comments deleted between checks are also unavailable. Slack reconnection can wait for an expired collector lease after an interrupted shutdown, and delivery recovery depends on Slack retention. This remains a local-machine implementation: Docker and the computer must stay running and awake. No new-service extension framework, recurring manager grant, notification inbox or mobile runtime was added.
