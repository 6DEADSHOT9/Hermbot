## Implemented behavior

**Connections** has account/access configuration, OAuth setup, standing permissions and external operation activity. Google and GitHub can use owner-initiated OAuth; Slack OAuth is implemented for an HTTPS callback, and local HTTP supports private bot and user tokens. Credentials, OAuth client secrets, refresh tokens and PKCE verifiers are encrypted with the existing configuration encryption key. Neither owner projections nor bots receive those secrets. An OAuth attempt is bound to its initiating browser and still-valid owner session, expires in ten minutes, is single-use, and checks connection and app revisions. Google and GitHub use PKCE. Refresh and Slack user-token rotation preserve the scoped connection policy. Rejected authentication asks the owner to reconnect.

The owner selects bots and actions independently of management grants. Resource restrictions apply to each action's explicit recipient/calendar/file/folder/channel/repository field. An omitted resource restriction permits every resource reachable by that action and provider token; search actions without a resource field search the token's accessible data. A connection can be shared with selected bots. Managers cannot inherit another bot's connection through delegation.

| Provider | Reads | Reviewed changes |
|---|---|---|
| Google Gmail | Search messages; read full message content | Send a new message or reply with explicit recipient, subject, body and optional thread/reply IDs |
| Google Calendar | Calendars, availability, events | Create, update or delete an event; creates expose attendee emails in the exact review |
| Google Drive | Search, read/download, export Docs/Sheets, import a supported file into the versioned library | Create a text file or Google document in an explicit folder |
| Slack | Search with a user token; list channels and read channel history with the bot token | Post a reviewed message or thread reply |
| GitHub | Repositories, issues, pull requests and files | Create/update issues, comment, create a pull request, create/update a file on a selected branch |
| MCP | Public HTTPS Streamable HTTP capability discovery | Every tool call requires review or explicit permission; server read-only annotations do not bypass authorization |

Bots discover their own actions with `hermbot_connectors`, then use `hermbot_connector`. External text is untrusted evidence. Existing delegation, dependencies and explicit artifact grants carry results between bots with different app access.

## Reviews, recovery and revocation

Each mutation freezes its exact arguments and connection revision in a connector review. The existing **Edit draft** form can replace those arguments; replacement creates a new review and invalidates the old approval. One unfinished external mutation is allowed per task. After **Allow once**, the worker waits for native execution to settle and rechecks task lifetime, management grant, connection policy, resource scope, payload hash and approval before sending the action.

Standing permissions specify one connection, bot, action and exact resource, with an expiry and usage limit. Dispatch rechecks revocation and limits. A committed dispatch marker is counted even if a subsequent database rollback loses the usage counter. An operation that may have happened remains **uncertain** and is never automatically repeated. **Connections → Activity → Reconcile outcome** records provider evidence and resumes the bot without replaying the request. Calendar event ID, Drive operation metadata and Slack client message ID help identify the original action. The October 19 Gmail parent read showed a different stored Message-ID from the locally supplied header: use actual provider message IDs/headers and corroborating evidence, and never infer that a send did not happen merely because the supplied header cannot be found. See C40.

Revoke removes local credentials and invalidates pending authorizations and standing permissions. It also attempts provider-side Google, Slack and OAuth GitHub token revocation. The UI reports whether the provider confirmed it. Imported GitHub personal tokens and MCP tokens must also be revoked at their provider. An already admitted action can finish before revocation takes effect; queued actions are rechecked.

Owner policy update, October 11, 2026: connections must not disable native tools. The connection-based blacklist and task-tree enforcement have been removed from discovery and execution; historical latch values are retained only as records. Every owner-enabled, configured tool remains available to connected bots and collaborators, including after revocation. Connector calls continue to enforce bot/action/resource scope, current connection revisions and exact review or standing permission for mutations. Credentials and backend configuration remain outside bot mounts. Runtime code is read-only, the managed plugin tree is root-owned, and the gateway runs as the Hermes user with no effective capabilities and no privilege escalation. Writable per-bot state, workspaces and browser profiles are preserved. Independently authenticated browser or terminal actions are outside connector approval coverage. Routing, preparation and human takeover still apply. Connection access changes still require affected bots to be idle.

MCP supports JSON and SSE responses, negotiated protocol versions 2025-11-25 / 2025-06-18 / 2025-03-26, bounded discovery and session teardown. Connections use public HTTPS endpoints with optional encrypted bearer tokens; private-network endpoints, stdio transports and MCP OAuth discovery are outside this implementation. Untrusted JSON schemas are bounded and cannot contain references or validation regexes. Changing an MCP endpoint clears credentials, discovered tools and permissions before reconnecting.

4. For MCP, add its public HTTPS endpoint, save a token (blank for a public server), discover tools, then edit access to select allowed tools. Discovery resets allowed actions so new capabilities are never automatically granted. See [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Imported tokens are saved privately but their account/scopes are checked on first use. Replace them when they expire; use OAuth for refresh. Keep `CONFIG_ENCRYPTION_KEY` with the existing private backup configuration. The forms do not save secrets in browser storage, clear them when closed and omit submitted private inputs from validation errors. API access logging is disabled so OAuth authorization codes and state are not logged in request URLs.

Unknown application outcomes block task retry and manager reassignment.
