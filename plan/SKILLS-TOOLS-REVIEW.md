## Practical limits

Skill relevance and requirement planning remain semantic model decisions. Metadata is optional; an undeclared requirement can still be discovered during execution, where the same current admission policy applies. No second classifier/model or keyword heuristic is introduced. A capability inventory describes permitted actions, not provider acceptance or account health; actual connector receipts and exact write approvals remain authoritative.

Enabled procedures are guidance, not an authority source. Native tool admission is enforced in the trusted single-owner Hermes runtime; it is not an OS sandbox for arbitrary processes previously started through terminal access. Connected task trees retain conservative native command/browser/write restrictions. Teammate discovery exposes planning facts without connection IDs, resources, account secrets, private memory or skill bodies. Private raw bodies remain in the requesting task's authenticated tool receipt, consistent with existing native execution history.

No acceptance in this change sends Slack messages, creates provider documents/issues/PRs or repeats old Phase 4 drafts. Linux staging/HTTPS, multi-user sharing and subscription provider authentication remain deferred follow-up work.
